# 从快速跑通，到一线愿意持续用

这是我围绕黑湖小工单做的两项现场适配产品原型：一个减少报工动作，一个重新思考车间公共屏上的个人绩效呈现。

在线体验：

- [项目说明页](https://edward-jiahualiu.github.io/blacklake-fieldfit-demos/)
- [智能快捷报工](https://edward-jiahualiu.github.io/blacklake-fieldfit-demos/quick-report/)
- [车间进度赛道](https://edward-jiahualiu.github.io/blacklake-fieldfit-demos/collaborative-progress/)

项目包含三个独立页面：

- 项目说明页：研究判断与两个原型入口
- `quick-report/`：智能快捷报工
- `collaborative-progress/`：车间进度赛道

两个 Demo 没有业务状态联动，也不连接真实工厂数据。刷新页面即可恢复初始演示状态。

## 为什么选择这两个问题

黑湖公开案例已经证明，小工单可以让计划员少跑现场、让管理者更快看到订单和工序进度。但同一批公开材料也记录过上线初期的抵触、漏报，以及赶工时数量不准等采用阻力。

这使我把问题从“系统能不能跑通”往后推了一步：

1. 一线在最忙的时候，能否持续留下可信记录？
2. 当个人绩效进入公共大屏，怎样保留进度可见性，又不过早把员工简化成一条排名？

山田机械案例中的驾驶舱展示过“员工绩效 Top5”。公开页面没有说明该指标的计算单位和公式，因此本项目不复刻它的算法，只把它作为现有呈现方式的事实锚点。

## Demo 1：智能快捷报工

场景是正在赶工的一线员工。当前工单、产品和工序已经准备好，主界面只保留一个动作：完成一批，点一下。

- 初始任务：`WO-018 / 铝合金阀体 A17 / 精车 OP20`
- 初始进度：`126 / 200`
- 默认步长：`+5`
- 点击立即入账，不增加草稿或二次确认
- 每次操作都能撤销最近一笔，并可连续撤销
- 管理员可以把步长改为 `+1 / +5 / +10 / 自定义`
- 支持按钮回弹、数字跳动、扩散反馈和轻微设备振动，不播放声音

这里的 AI 不以聊天框出现。它根据已分配工单、当前工序、近期节拍和管理员规则，提前建议任务与步长；一线仍然只做一次明确点击。当前 Demo 用本地规则模拟这一行为，没有发送模型请求。

要验证的不是“大按钮是否好看”，而是每次有效记录所需的动作是否变少，以及漏报、补录和更正是否随之下降。

## Demo 2：车间进度赛道

它替代的是车间公共屏上的个人 Top5，而不是老板手机里的明细表。

- 七名虚构员工沿同一条固定赛道前进
- 赛车位置代表个人当班计划完成率
- 公共屏只露出头像，不写姓名、件数、名次或“落后者”
- 看台、维修站、检查区和仓库只构成赛车场氛围，不对应生产节点
- 模拟器用固定随机种子复现一段生产过程，可开始、暂停和重置
- 员工头像可从本机临时替换；文件不上传，刷新后清除
- 手机端默认回到中性列表，按工位排列，而不是按进度排序

不同工序不能直接比较原始件数，因此赛车位置采用：

```text
赛车进度 = 已确认合格件数 × 标准工时 × 工序系数 ÷ 个人当班计划标准工作量
```

AI 的职责是根据历史节拍与工序数据建议标准工时、工序系数和异常校准。管理员能看到依据、调整数值并说明覆盖原因。这个换算是我的产品方案，不是黑湖公开材料中已经确认的现有功能。

赛车地图仍然是一种个人间比较。它是否比条形 Top5 更容易理解、更愿意观看，又不会增加压力感与不公平感，需要通过现场实验回答，不能由视觉稿代替结论。

## AI 功能边界

| 环节 | 输入 | 输出 | 人工控制 |
|---|---|---|---|
| 快捷报工 | 已分配工单、当前工序、近期节拍、管理员规则 | 当前任务与建议步长 | 管理员可改为固定步长；一线可立即撤销 |
| 进度换算 | 合格件数、标准工时、工序系数、当班计划 | 个人当班计划完成率 | 管理员查看依据、覆盖系数并记录原因 |

现阶段先用确定性本地数据验证交互。只有当任务匹配错误、节拍建议偏差和公平性反馈都能被记录后，才有必要比较规则、传统模型和大模型方案。这样可以避免为了展示 AI 而增加一线操作。

## 证据怎样影响设计

| 资料 | 它支持的判断 | 对应设计 |
|---|---|---|
| [黑湖小工单｜山田机械案例](https://www.xiaogongdan.cn/case/yamada-machinery-data-production) | 官方公开驾驶舱曾展示个人绩效 Top5 | 把现有呈现作为对照组，而不是假设其算法 |
| [黑湖小工单｜大兴抛光案例](https://www.xiaogongdan.cn/case/daxing-polishing-order-tracking)、[MSX 机械案例](https://www.xiaogongdan.cn/caseDetailContent/blog/998) | 具名案例中出现过初期抵触、漏报、培训和数量准确性问题 | 优先减少赶工时的输入动作 |
| [Breiter et al., 2022](https://doi.org/10.1016/j.ifacol.2022.09.469) | 51 名潜在用户测试显示，工作相关性和感知有用性与使用意愿、人工数据质量有关 | 不让一线重复填写系统已经知道的上下文 |
| [Ohlig et al., 2020](https://doi.org/10.1108/IJQSS-04-2020-0051) | 6 家制造 SME、27 次访谈显示，管理者和一线对 KPI 的理解与价值感可能不同 | 公共屏与老板手机使用不同的信息层级 |
| [Ravid et al., 2023](https://doi.org/10.1111/peps.12514) | 94 个独立样本、23,461 人的元分析中，电子绩效监控没有稳定提升绩效，却与更高压力相关 | 把压力感、公平感和被监控感设为实验护栏 |
| [Liu et al., 2018](https://doi.org/10.1002/hfm.20723) | 中国设备制造场景表明游戏化工作设计值得继续实验 | 制作可测试的赛车原型，不直接宣称有效 |
| [工信部“小快轻准”指引（2026）](https://wap.miit.gov.cn/jgsj/qyj/wjfb/art/2026/art_2ce9b878c2c34be4b8e0f9b275b22fbd.html) | 简单配置、短培训、用户反馈、安全与服务被放入同一评价框架 | 把“适配”理解为部署之后仍能持续使用 |

## 下一步怎么验证

### 快捷报工

比较原流程与大按钮流程，完成同一组生产记录任务。观察：

- 每笔有效记录的点击数和完成时间
- 报工延迟、漏报、重复、补录与撤销率
- 与现场基准记录的一致性
- 一线主观负担和管理员核对工时

### 进度呈现

至少比较三组，而不是只做新旧两组：

- A：传统 Top5 横向条形排名
- B：相同个人工作量数据驱动的赛车地图
- C：无显式名次的个人进度／团队汇总

共同观察进度判断准确率、完成判断时间、持续查看意愿、压力感、公平感、被监控感、策略性报工，以及是否只追数量而忽略质量。

如果 B 没有优于 A，或者压力护栏变差，就不应因为视觉新颖而上线。若 C 的结果更好，产品方向应转向减少公开比较，而不是继续优化赛车皮肤。

## 本地运行

需要 Node.js 22 与 pnpm。

```bash
pnpm install
pnpm dev
```

生产构建：

```bash
pnpm build
```

构建结果位于 `dist/`。仓库内的 GitHub Actions 会在 `main` 分支更新后自动发布 GitHub Pages。

## 目录

```text
src/home/                    项目说明页
src/quick-report/            智能快捷报工
src/collaborative-progress/  车间进度赛道
src/shared/                  共用视觉基础
docs/PRODUCT_SPEC.md         产品与验收边界
src/assets/                  原创赛道与赛车素材
```

这是个人求职研究与产品原型，不是黑湖官方项目。品牌名称仅用于说明研究对象；页面中的员工、工单与产量均为虚构数据。
